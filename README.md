# LAB01 — La mia identità tecnica su GitHub

## Costruisco il mio profilo ed entro nella community della classe

Benvenuto/a nel primo laboratorio su GitHub. Non devi conoscere Git e non devi
installare alcun programma: per questo laboratorio basta il browser.

Procedi nell'ordine indicato. Il profilo e il portfolio che inizi oggi non sono
un esercizio usa-e-getta: potranno crescere con i tuoi progetti durante tutto il
triennio.

Durata indicativa: **2 ore**.

## 🎯 Missione

Alla fine del laboratorio avrai:

- controllato il tuo profilo GitHub;
- creato e iniziato a compilare il README del tuo profilo;
- verificato che ciò che pubblichi sia adatto a essere pubblico;
- partecipato alla community del Class Hub `3BINF`;
- raccolto le evidenze nella tua Issue personale LAB01.

## 🧭 Come lavorare

Per ogni missione segui sempre lo stesso ciclo:

**Leggi → Fai → Controlla → Spunta → Commenta → Continua.**

Quando trovi un checkpoint, fermati: passa oltre soltanto se il risultato sullo
schermo corrisponde a quello descritto. Se non corrisponde, chiedi aiuto usando
la regola delle 3P spiegata nella guida.

## 1. Crea la tua scheda di lavoro

1. In alto nel repository, seleziona la scheda **Issues**.
2. Seleziona **New issue**.
3. Scegli il modello **LAB01 — La mia identità tecnica su GitHub**.
4. Completa il titolo che inizia con `LAB01 -` aggiungendo il tuo username.
5. Non devi compilare in anticipo le missioni successive: la Issue sarà la tua scheda di avanzamento.
6. Seleziona **Create**.

> 🛑 CHECKPOINT
> Deve essere visibile una Issue con titolo che inizia con `LAB01 -`. È la tua
> scheda personale: tornerai qui durante il laboratorio.

## 2. Segui la guida nell'ordine

Apri [STUDENT-GUIDE.md](STUDENT-GUIDE.md) e completa una missione alla volta.
Usa [la mini guida Markdown](docs/markdown-mini-guida.md) solo quando ti viene
chiesto. Prima di rendere pubblico il profilo, usa la
[checklist privacy](docs/privacy-checklist.md).

Per ogni missione:

1. svolgi l'attività;
2. controlla il risultato;
3. torna alla tua Issue LAB01 e spunta le checkbox corrispondenti;
4. aggiungi **un commento** con l'evidenza richiesta.

I commenti costruiscono una cronologia del lavoro: non modificare il corpo della
Issue per inserire le evidenze.

> Per oggi puoi considerare **Commit changes** come “Conferma questa modifica”.
> Studieremo più avanti il significato tecnico di *commit*.
