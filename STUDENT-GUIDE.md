# Guida studente — LAB01

Segui le missioni nell'ordine. Dopo ogni attività torna alla tua Issue LAB01,
spunta ciò che hai concluso e aggiungi **un commento** con l'evidenza richiesta.

> 🛑 CHECKPOINT
> Non continuare finché il risultato non corrisponde a quello indicato.

## Missione 1 — Controlla il tuo profilo

### LEGGI

Il tuo profilo è la pagina pubblica collegata al tuo username GitHub.

### FAI

1. Apri [GitHub](https://github.com) e accedi al tuo account.
2. Guarda in alto a destra.
3. Fai clic sulla tua immagine oppure sull'icona del tuo account.
4. Seleziona **Your profile**.
5. Guarda l'indirizzo nella barra del browser.
6. Copialo.

### CONTROLLA

L'indirizzo deve iniziare con `https://github.com/` e terminare con il tuo
username.

### SPUNTA

Torna alla tua Issue LAB01 e spunta la Missione 1.

### MOSTRA L'EVIDENZA

Aggiungi un commento alla Issue:

```text
Missione 1 completata
Profilo GitHub: https://github.com/tuo-username
```

## Missione 2 — Crea il repository speciale del profilo

### LEGGI

Un repository è uno spazio GitHub dedicato a un progetto. GitHub riconosce in
modo speciale un repository pubblico che ha esattamente lo stesso nome del tuo
username: il suo README può comparire nel tuo profilo.

### FAI

1. Guarda in alto a destra su GitHub e seleziona il pulsante **+**.
2. Seleziona **New repository**.
3. Nel campo **Repository name**, scrivi il tuo username esattamente come lo vedi
   nel profilo.
4. Controlla che GitHub mostri un messaggio che indica che è un repository
   speciale per il profilo.
5. Seleziona **Public**.
6. Seleziona **Add a README file**.
7. Seleziona **Create repository**.

### CONTROLLA

Nella pagina del nuovo repository, proprietario e nome devono essere uguali:
`username/username`. Deve essere presente il file `README.md`.

> 🛑 CHECKPOINT
> Se il nome del repository non coincide con il tuo username, fermati e chiedi
> aiuto prima di proseguire.

### SPUNTA

Torna alla tua Issue LAB01 e spunta la Missione 2.

### MOSTRA L'EVIDENZA

Aggiungi un commento alla Issue:

```text
Missione 2 completata
Repository del profilo: https://github.com/tuo-username/tuo-username
```

## Missione 3 — Costruisci il Profile README

### LEGGI

Il README è il testo di presentazione del repository. In questo caso diventa una
parte del tuo profilo. Scrivi in modo vero e rispettoso: **non inventare
competenze che non possiedi**. Dire di essere all'inizio del percorso è del tutto
accettabile.

### FAI

1. Nel repository `username/username`, fai clic su `README.md`.
2. Seleziona l'icona della matita **Edit**.
3. Seleziona tutto il testo presente e sostituiscilo con questo modello.
4. Personalizza le parti con `...`.

```markdown
# Ciao! 👋

Sono uno studente di Informatica e questo è l'inizio
del mio portfolio tecnico.

## 👤 Qualcosa su di me

...

## ❤️ Le mie passioni

- ...
- ...
- ...

## 💻 Tecnologia ed esperienze

Ho già avuto occasione di utilizzare o conoscere:

- ...
- ...
- ...

## 🧠 Una cosa che potrei insegnare ai miei compagni

...

## 🔍 Cosa mi piacerebbe imparare

...

## 🚀 Un progetto che mi piacerebbe realizzare

...

## 🎯 Guardando al futuro

...
```

5. Guarda l'anteprima **Preview** oppure il riquadro di anteprima, se presente.
6. Controlla che titoli ed elenchi siano leggibili.
7. Seleziona **Commit changes**.
8. Nella finestra che compare, seleziona di nuovo **Commit changes** per
   confermare la modifica.

> Per oggi puoi considerare **Commit changes** come “Conferma questa modifica”.
> Studieremo più avanti il significato tecnico di *commit*.

### CONTROLLA

1. Torna su **Your profile**.
2. Scorri sotto le informazioni del profilo.
3. Deve essere visibile la presentazione che hai scritto.

> 🛑 CHECKPOINT
> Se la presentazione non è visibile, verifica prima che il repository sia
> pubblico e si chiami esattamente come il tuo username.

### SPUNTA

Torna alla tua Issue LAB01 e spunta la Missione 3.

### MOSTRA L'EVIDENZA

Aggiungi un commento alla Issue:

```text
Missione 3 completata
Nel README ho aggiunto: ...
```

### Solo il Markdown necessario oggi

Puoi consultare [la mini guida Markdown](docs/markdown-mini-guida.md). Oggi ti
servono soltanto titoli, elenchi, grassetto e link.

## Missione 4 — Privacy Check

### LEGGI

Il profilo è pubblico. Prima di pubblicare, chiediti se saresti tranquillo/a a
mostrare il contenuto contemporaneamente a un compagno, a un docente e a una
futura azienda.

### FAI

1. Apri [la checklist privacy](docs/privacy-checklist.md).
2. Rileggi il README del tuo profilo.
3. Controlla ogni punto della checklist.
4. Se trovi un dato non adatto, torna su `README.md`, seleziona **Edit**,
   correggilo e conferma con **Commit changes**.

### CONTROLLA

Il README non contiene informazioni riservate o non necessarie.

### SPUNTA

Torna alla tua Issue LAB01 e spunta la Missione 4.

### MOSTRA L'EVIDENZA

Aggiungi un commento alla Issue:

```text
Missione 4 completata
Privacy controllata: sì
```

## Missione 5 — Entro nella community della classe

### LEGGI

Il Class Hub della classe è lo spazio comune per confrontarsi. La presentazione
va pubblicata lì, non nel tuo repository individuale.

### FAI

1. Apri il Class Hub: https://github.com/Torriani-AS2026/3BINF-github-hub
2. Seleziona la scheda **Discussions**.
3. Apri la Discussion **👋 Presentiamoci tecnicamente**.
4. Leggi almeno due presentazioni di compagni.
5. Seleziona il campo per rispondere.
6. Copia questo modello e personalizzalo.

```markdown
### Ciao! 👋

Con la tecnologia ho già avuto esperienza con ...

Durante il triennio mi piacerebbe imparare ...

Una cosa che potrei insegnare ai miei compagni è ...
```

profilo.

## Missione 7 — Impariamo a chiedere aiuto

### LEGGI

Nel nostro corso useremo questa convenzione didattica, che non è una regola
universale di GitHub:

| Useremo una Issue per… | Useremo una Discussion per… |
| --- | --- |
| un'attività concreta | una domanda |
| un problema da correggere | un confronto |
| un miglioramento da realizzare | una richiesta di aiuto |
|  | una proposta da discutere |

Per chiedere aiuto usa la regola delle **3P**:

1. **PROBLEMA** — Cosa volevi ottenere?
2. **PROVA** — Che cosa è successo?
3. **PROCESSO** — Che cosa hai già tentato?

### FAI

1. Leggi questa richiesta poco utile: `Prof non funziona. Cosa devo fare?`
2. Trasformala in una richiesta con le 3P. Per esempio:

```text
PROBLEMA: volevo vedere il README nel mio profilo.
PROVA: vedo il repository, ma il testo non compare nel profilo.
PROCESSO: ho controllato che il repository sia pubblico e che il nome coincida con il mio username.
```

3. Se durante LAB01 hai un dubbio reale, apri il Class Hub: https://github.com/Torriani-AS2026/3EINF-github-hub
4. Seleziona **Discussions** e apri **🆘 Aiuto LAB01**.
5. Pubblica lì la richiesta usando le 3P.

### CONTROLLA

Una buona richiesta permette a chi legge di capire obiettivo, risultato ottenuto
e tentativi già fatti.

### SPUNTA

Torna alla tua Issue LAB01 e spunta la Missione 7 quando hai preparato una
richiesta con le 3P oppure ne hai pubblicata una reale nel luogo indicato.

### MOSTRA L'EVIDENZA

Aggiungi un commento alla Issue:

```text
Missione 7 completata
PROBLEMA: ...
PROVA: ...
PROCESSO: ...
```
